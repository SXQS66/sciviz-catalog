富集分析完整十法

ORA / GSEA / ssGSEA / GSVA … 十种方法的适用前提与选择路径。

富集ORAGSEA方法学

三种范式：回答的问题不同

富集分析的本质，是把零散的分子变化翻译成可理解的生物学功能。按统计思路分成三代：ORA（过表征分析）、FCS（功能集打分，如 GSEA1 / ssGSEA / GSVA2）、PT（通路拓扑分析，如 SPIA3 / NetGSA / Clipper / DEGraph）。三者不是替代关系：ORA 问「有没有」，FCS 问「有多少」，PT 问「在哪里」。

范式输入统计思路代表方法局限
ORA
过表征分析		已按阈值筛过的差异基因列表超几何 / Fisher 精确检验，比较命中比例与背景比例GO、KEGG、Reactome结论随阈值变化；忽略基因间关系与排序
FCS
功能集打分		全基因排序列表或表达矩阵Kolmogorov–Smirnov 类统计量，看基因集是否整体偏移GSEA、ssGSEA、GSVA仍把通路当作无序基因集合
PT
通路拓扑分析		表达数据 + 通路拓扑结构把基因在通路中的位置、上下游关系加权进统计量SPIA、NetGSA、Clipper、DEGraph依赖高质量通路注释，复现门槛高

选方法的顺序应该是「数据能提供什么输入 → 我想回答哪一层问题 → 需要多深的机制证据」，而不是「哪个方法更高级」。

ORA 三剑客：GO / KEGG / Reactome

数据库组织方式强项典型问法
GO三个正交维度：BP / CC / MF覆盖面最广、条目最细，适合无偏扫描这批基因和哪些生物学功能有关？
KEGG手工绘制的通路地图一张图看清上下游，读者友好差异基因集中在哪些经典通路？
Reactome以「反应」为单位、层级嵌套粒度最细，可定位到具体反应步骤变化发生在哪个反应环节？

互补而非替代：KEGG 无显著通路时，常见原因是信号集中在某个细分反应、还没汇成「经典通路」——此时换 Reactome 往往能打开局面（数据库分工见 No.035）。

FCS 三兄弟：GSEA / ssGSEA / GSVA

方法输入输出典型问法
GSEA全基因排序列表 + 分组NES（方向 + 强度）与 leading edge某基因集是否整体偏向变化谱的一端？
ssGSEA表达矩阵（无需分组）每个样本 × 每条通路的富集分数单个样本的通路活性高不高？
GSVA表达矩阵（跨样本核密度估计）通路活性矩阵样本之间通路活性有无系统差异？

一句话分工：GSEA 做组间比较，ssGSEA / GSVA 做个体特征提取。后两者输出「样本 × 通路」矩阵，可以直接交给热图、聚类或生存分析，也是单细胞与多组学整合最常用的入口。

PT 四法：把拓扑结构算进去

拓扑方法的共同点，是在 ORA / FCS 之上再加一层信息：基因在通路里的位置（上游还是下游），或者边（调控关系是否存在）。

方法核心思想独特问答
SPIA合并差异倍数与拓扑位置，输出 PNDE（富集）与 PPERT（拓扑扰动）扰动发生在通路的上游还是下游？
NetGSA把网络边权重写进模型，看调控结构是否整体重编程网络连接方式变了没有？
Clipper图分解 + 两步检验，先判整体、再定位子结构通路里哪一段子结构最受扰动？
DEGraph多元 Hotelling T² 检验整张网络整个子网络在两组间是否整体差异？

使用建议：优先 SPIA / NetGSA（更稳健），Clipper / DEGraph 作为深度补充。拓扑方法灵敏度高、特异性偏低，结论必须与 ORA / FCS 交叉验证后再写进文章。

三步定位：我的数据该用哪种

步骤看什么结论
① 看输入只有差异基因列表 / 有全基因排序 / 有完整表达矩阵ORA / GSEA / ssGSEA·GSVA·PT
② 看问题组间差异 / 个体特征 / 精细机制GO·KEGG + GSEA / ssGSEA·GSVA / Reactome + SPIA·NetGSA
③ 看深度初筛 / 深化 / 精雕GO + KEGG → Reactome + GSEA → 拓扑方法

推荐组合：GO + KEGG + Reactome（打底）→ GSEA（验证）→ SPIA（机制）。重点不是把十种方法都跑一遍，而是想清楚数据能回答到哪一层——跑不动的方法，硬套只会得到无法解释的 p 值。

论文里怎么写

  • 先给宏观方向——GO / KEGG 建立读者预期；
  • 再定位具体环节——Reactome / GSEA 把结论收窄；
  • 必要时补拓扑证据——SPIA / NetGSA 支撑「上游 vs 下游」的判断；
  • 措辞落到环节——写「通过 XX 通路中 YY 环节的 ZZ 机制」，而不是笼统的「通过 XX 通路」。

没有「最好」的方法，只有「最合适」的方法：先问数据能回答什么，再选工具，最后才谈解读。
