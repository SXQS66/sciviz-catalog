富集分析的十种方法

富集分析的本质，是把零散的分子变化翻译成可理解的生物学功能。按统计思路可分三大范式：ORA（过表征分析）、FCS（功能集打分，如 GSEA1 / ssGSEA / GSVA2）、PT（通路拓扑分析，如 SPIA3 / Clipper / DEGraph）。本文把十种常用方法放进同一张地图：每种方法回答什么问题、输入是什么、什么时候该换。

富集分析的三大范式

ORA · FCS · PT — 三代方法的演进

第一代 · ORA

过表征分析

  • 输入：差异基因列表
  • 统计：超几何检验 / Fisher 精确检验
  • 代表：GO、KEGG、Reactome
  • 优点：直观、易解释
  • 局限：依赖人为阈值、忽略基因间关系

第二代 · FCS

功能集打分

  • 输入：全基因排序列表
  • 统计：Kolmogorov-Smirnov 类统计量
  • 代表：GSEA、ssGSEA、GSVA
  • 优点：不设阈值、发现微弱协调信号
  • 局限：仍忽略通路内部结构

第三代 · PT

通路拓扑分析

  • 输入：差异表达 + 通路结构
  • 统计：整合拓扑位置、相互作用
  • 代表：SPIA、NetGSA、Clipper、DEGraph
  • 优点：考虑基因在通路中的位置权重
  • 局限：依赖高质量通路注释

三者不是替代关系，而是层层递进 — 从“有没有”到“有多少”再到“在哪里”

ORA 三剑客 · GO / KEGG / Reactome

差异基因列表 → 功能/通路富集

GO

Gene Ontology

  • 三大维度：BP / CC / MF
  • 覆盖面最广（~42.3% 人类基因注释）
  • 适合回答：这批基因跟哪些生物学功能有关？

KEGG

Kyoto Encyclopedia

  • 经典通路地图 · 直观
  • 覆盖 ~12.4% 人类基因注释
  • 适合回答：差异基因集中在哪些经典通路？

Reactome

反应级通路数据库

  • 以“生物反应”为核心 · 层级结构
  • 覆盖 ~26.3% 人类基因注释
  • 适合回答：变化发生在哪个具体反应环节？

核心洞察 GO 看功能全貌 · KEGG 看通路框架 · Reactome 看反应细节 — 三者互补

KEGG 无结果时，Reactome 往往是突破口 — 因为信号可能集中在某个具体反应步骤

FCS 三兄弟 · GSEA / ssGSEA / GSVA

全基因排序 → 基因集整体偏移

GSEA

基因集富集分析

  • 输入：全基因排序列表 + 分组
  • 输出：NES（方向 + 强度）
  • 适合回答：某基因集是否整体偏向变化谱一端？

ssGSEA

单样本 GSEA

  • 输入：表达矩阵（无需分组）
  • 输出：每个样本 × 每条通路的富集分数
  • 适合回答：每个样本的通路活性高不高？

GSVA

基因集变异分析

  • 输入：表达矩阵（跨样本核密度估计）
  • 输出：通路活性矩阵（与 ssGSEA 目标相同）
  • 适合回答：样本间通路活性是否存在系统差异？

关键区别 GSEA 需要分组信息，ssGSEA/GSVA 不需要 — 后者适合无监督探索和个体化分析

GSEA = 组间比较 · ssGSEA/GSVA = 个体特征提取

PT 方法（上）· 位置与连接

SPIA 看“位置” · NetGSA 看“连接”

PT 方法共同点：在 ORA/FCS 基础上，额外整合通路拓扑结构（基因位置、边方向、网络关系）

SPIA

信号通路影响分析

  • 核心思想：整合差异倍数 + 拓扑位置
  • 计算 PNDE（ORA 富集）和 PPERT（拓扑扰动）
  • 适用场景：信号通路（有向边），想知道“上游 vs 下游”哪个环节受扰动

NetGSA

基于网络的基因集分析

  • 核心思想：整合差异表达 + 网络边权重
  • 不仅看基因是否差异，还看基因间的相互作用模式
  • 适用场景：已知基因-基因网络（KEGG/Reactome），研究调控网络重编程

SPIA 回答“在通路哪个位置” · NetGSA 回答“网络连接怎么变”

PT 方法（下）· 子结构与全网络

Clipper 找“子结构” · DEGraph 验“全网络”

Clipper

图分解通路分析

  • 核心思想：基于图分解理论，两步检验
  • ① 检验通路均值/协方差 ② 定位最相关信号路径
  • 适用场景：想找通路内“哪一段子结构”最受扰动，无需 p 值的 FDR 控制

DEGraph

差异表达图检验

  • 核心思想：多元 Hotelling T² 检验
  • 直接检验整个基因网络是否在两组间差异表达
  • 适用场景：敏感性要求极高，但特异性相对较低，需交叉验证

PT 方法使用建议优先用 SPIA/NetGSA（更稳健），Clipper/DEGraph 作为深度补充，结合 ORA/FCS 结果交叉验证。

Clipper 找“哪一段” · DEGraph 问“整个网络” — 两者视角互补

实际分析 · 怎么选？

三步定位法

第一步 · 看输入

  • 只有差异基因列表 → GO / KEGG / Reactome
  • 有全基因排序 → GSEA
  • 有完整表达矩阵 → ssGSEA / GSVA / PT 方法

第二步 · 看问题

  • 组间差异 → GO/KEGG/Reactome + GSEA
  • 个体特征 → ssGSEA / GSVA
  • 精细机制 → Reactome + SPIA / NetGSA

第三步 · 看深度

  • 初筛：GO + KEGG（宏观方向）
  • 深化：Reactome + GSEA（精细定位）
  • 精雕：SPIA / NetGSA / Clipper / DEGraph（拓扑洞察）

推荐组合：GO + KEGG + Reactome（基础）→ GSEA（验证）→ SPIA（深度机制）

富集分析的重点不是把所有方法都跑一遍，而是想清楚数据能回答什么问题

核心要点

  • 富集分析有三大范式、十种常用方法
  • ORA 回答“有没有” · FCS 回答“有多少” · PT 回答“在哪里”
  • 没有“最好”的方法，只有“最合适”的方法

论文写作建议

  • 先展示 GO/KEGG → 提出宏观方向
  • 再用 Reactome/GSEA → 定位具体环节
  • 必要时用 SPIA/NetGSA → 提供拓扑证据
  • 避免只写“通过 XX 通路”，而是 “通过 XX 通路中 YY 环节的 ZZ 机制”

可靠的机制研究 = 高质量数据 + 正确的方法选择 + 深入的生物学解读

下次分析时，问自己：我的数据适合哪种输入？我想回答什么问题？我需要多深的机制洞察？
