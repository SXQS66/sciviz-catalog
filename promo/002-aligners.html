比对软件三强：STAR · HISAT2 · Bowtie2 怎么选

后缀数组还是 FM 索引？为什么 Bowtie2 不能拿来跑常规 RNA-seq？三款比对器的原理、命令与选型对照。

STARHISAT2Bowtie2比对RNA-seq

为什么会有「能不能比对 RNA-seq」的区别

比对器的核心任务一样：把一段几十到几百 bp 的 read 放回参考基因组的正确位置。区别出在剪接比对（spliced alignment）：mRNA 成熟时内含子被剪掉，RNA-seq 的 read 跨越剪接点后，在基因组上会被切成两段、中间隔着几万 bp——比对器必须主动允许「大缺口、且缺口边界符合 GT-AG 规则」的比对方式。能否处理这种缺口，直接把常用软件分成两派：

软件索引原理剪接比对人类基因组内存典型用途
STAR非压缩后缀数组（MPRF）✅ 原生约 30 GB常规 RNA-seq 首选，新剪接点发现
HISAT2层次化 FM 索引（图基因组）✅ 原生约 8 GB低内存环境、大样本量 RNA-seq
Bowtie2FM 索引（BWT）❌ 不支持约 4 GB小 RNA-seq、ChIP-seq、DNA 重测序
BWA-MEM4FM 索引（BWT）❌（不适合）约 15 GBDNA-seq 事实标准，WGS/WES 比对

一句话选型：常规 bulk RNA-seq 用 STAR 或 HISAT2（内存够选 STAR，内存紧张选 HISAT2）；小 RNA（18–30 bp，不跨内含子）用 Bowtie2；DNA 测序用 BWA-MEM。三者输出的都是 SAM/BAM，下游定量与质控流程完全通用（参见 No.001）。

STAR：速度换内存的「全能型」

STAR1用非压缩后缀数组做种子定位，搜索 unparalleled 的速度与高唯一比对率（人类样本常见 75–90%），且能发现未知剪接点——这也是它成为 ENCODE 官方流水线比对器的原因。代价是建索引与比对都需要大内存（人类基因组约 30 GB），建议在 64 GB 内存机器或 HPC 上运行。完整命令在 No.001 已给过，这里补一个进阶选项：

# 常规比对（详见 No.001）
STAR --runThreadN 12 --genomeDir star_index \
  --readFilesIn clean/SRR_1.fq.gz clean/SRR_2.fq.gz \
  --readFilesCommand zcat \
  --outSAMtype BAM SortedByCoordinate \
  --quantMode GeneCounts \
  --outFileNamePrefix star/SRR.

# 两遍法（2-pass）：先扫一遍找新剪接点，再用它辅助重比
# 每个样本独立检测，可显著降低假阳性剪接点
STAR --twopassMode Basic --runThreadN 12 --genomeDir star_index \
  --readFilesIn clean/SRR_1.fq.gz clean/SRR_2.fq.gz \
  --readFilesCommand zcat \
  --outSAMtype BAM SortedByCoordinate \
  --outFileNamePrefix star/SRR.

什么时候开 2-pass：要往上做可变剪接分析（rMATS、SUPPA）或新转录本组装（StringTie）时建议开；纯差异表达分析收益有限。--twopassMode Basic 是样本内 2-pass；多样本统一做法是先用 --sjdbFileChrStartEnd 合并所有样本的剪接点重建索引（即 ENCODE 的 2-pass 流水线）。

HISAT2：内存友好、图索引的「轻骑兵」

HISAT22用一组「全局 FM 索引 + 大量局部小索引」的层次化设计，把人类基因组索引内存压到 8 GB 左右，普通工作站就能跑；其图基因组设计还能区分常见 SNP 位点，减少个人参考序列造成的错配。比对的 read 会被送到 StringTie 等组装器时，记得加 --dta：

# 建索引：把 GTF 里的剪接点/外显子喂给 hisat2-build
extract_splice_sites.py gencode.vM36.annotation.gtf   # 随 HISAT2 附带的脚本 > ss.txt
extract_exons.py gencode.vM36.annotation.gtf > exon.txt
hisat2-build -p 12 --ss ss.txt --exon exon.txt Genome.fa hisat2_index/genome

# 比对（TruSeq 反向链双端数据 → --rna-strandness RF）
hisat2 -p 12 -x hisat2_index/genome \
  -1 clean/SRR_1.fq.gz -2 clean/SRR_2.fq.gz \
  --dta --rna-strandness RF \
  -S SRR.sam

# 输出是 SAM，转 BAM 并排序索引
samtools sort -@ 8 -o SRR.bam SRR.sam
samtools index SRR.bam

省事路线：HISAT2 官网（daehwankimlab.github.io/hisat2）提供人类等常用物种的预建索引直接下载，跳过建索引步骤；预建索引与自建索引要锁定同一版本，别混用。其 lib_format_counts.json 式的链型自检没有 Salmon 直接，判断链型仍建议看 STAR 列或 RSeQC。

Bowtie2：短 reads 的「精准手」，但别碰常规 RNA-seq

Bowtie23基于 BWT 的 FM 索引，内存小、对短 reads（尤其 ≤ 100 bp 的无内含子场景）又快又准，支持 end-to-end 与 local 两种模式、错配与小的 indel，四档预设灵敏度从 --very-fast 到 --very-sensitive（默认 --sensitive）：

# 建索引（注意：它的索引与 STAR/HISAT2 互不通用）
bowtie2-build Genome.fa bt2_index/genome

# 小 RNA-seq 单端比对（18–30 bp，默认端到端模式）
bowtie2 -p 12 -x bt2_index/genome \
  -U clean/miRNA.fq.gz \
  -S mirna.sam

# DNA / ChIP-seq 双端比对，更高灵敏度，直接管道进 samtools
bowtie2 --very-sensitive -p 12 -x bt2_index/genome \
  -1 R1.fq.gz -2 R2.fq.gz | samtools sort -@ 8 -o out.bam

红线：Bowtie2 不做剪接比对——常规 RNA-seq 的 read 跨内含子时整条 read 比不上，会出现「比对率只有 50–60% 且大量 reads 落在错误位置」的假象。小 RNA（miRNA/siRNA，18–30 bp，读段内基本无内含子）才是它的主场。如果你的 FASTQ 是 100 bp 以上 mRNA 测序，请回到 STAR / HISAT2。

无论选谁，下游都一样：samtools index5 建 BAM 索引 → featureCounts 定量 → Count 矩阵交给 DESeq2（整套命令见 No.001）。链特异性参数对照也列在上表——TruSeq 反向链数据对应 STAR 第 4 列 / HISAT2 RF / featureCounts -s 2。

一项目一软件：不同比对器的 counts 结果存在系统性差异，同一项目的所有样本必须用同一软件、同一索引版本、同一参数跑完。换软件 = 重跑全部分析，并在方法学里写明版本。
