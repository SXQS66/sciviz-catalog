ORA + GSEA 联合富集策略

超几何检验回答「有没有」，GSEA 回答「趋势在不在」，两套结果怎么合起来读。

ORAGSEA富集联合分析

ORA 与 GSEA：协同而非互斥

富集分析的两大范式各有明确分工：ORA（超几何检验）基于阈值筛出的差异基因列表，做「是否过量代表」的二元检验；GSEA1 则把全部基因按 log₂FC 等统计量排序，不设硬阈值，检测基因集是否整体偏向排序顶端或底端。

ORAGSEA
输入差异基因列表（|log₂FC| ≥ 1，FDR < 0.05）全基因排序列表（无阈值）
统计超几何检验，p + BH 校正富集得分 ES / NES + 排列检验
优势直观易解释，经典可靠，适合上下调分开做无信息损失，捕捉微效协同变化
局限依赖主观阈值，丢失弱而协同的信号结果依赖排序统计量，解读更抽象
常用工具clusterProfiler3fgsea2 / clusterProfiler3（MSigDB、KEGG）

为什么要联合？ORA 聚焦「强信号通路」，GSEA 捕获「全局趋势通路」；两者交集给出高置信度的生物学模块，能同时压低假阳性与假阴性。

第 1–2 步 · 方向性 ORA 与通路瘦身

上下调必须分开富集：混合会让正负调控互相抵消（促炎模型中，上调富集「炎症反应」、下调富集「氧化磷酸化」，意义完全不同）。随后按 No.013 的四条标准瘦身——富集基因数 10–100、FDR < 0.05、生物学相关性优先、富集倍数排序——每个方向保留 3–8 条核心通路。植物激素处理番茄的模拟示例：

方向核心通路p.adjust基因数
上调植物激素信号转导2.1e-0538
上调MAPK signaling pathway0.000329
下调光合作用-天线蛋白1.2e-0421

第 3 步 · GSEA 全局富集与共识通路

以全部基因按 log₂FC 从高到低排序，用 MSigDB / KEGG 基因集做 GSEA，排列检验得 NES 与 FDR。常用显著阈值：|NES| > 1.5 且 q < 0.25（GSEA 官方惯例，可按研究收紧）。Leading-edge 指对富集得分贡献最大的基因，位于排序顶端/底端的核心区，往往是通路调控的关键因子。

把 GSEA 显著通路与 ORA 富集通路取交集，得到「共识通路」：

通路ORA p.adjGSEA NES共识状态
MAPK signaling pathway0.00122.13✅ 共识核心
Plant hormone signal transduction2.1e-051.98✅ 共识核心
Endocytosis0.0231.32⚠️ ORA 边缘

共识通路同时具备强差异驱动与全局协同趋势，优先用于下游基因筛选。从 GSEA 显著通路提取全部 leading-edge 基因（通常 80–200 个，示例：MAPK3、WRKY33、CDPK、ERF1），它们是各通路富集的核心贡献者。

第 4 步 · 三重交集锁定高置信靶标

  1. 集合 A——ORA 核心通路内的差异基因；
  2. 集合 B——GSEA 显著通路的 leading-edge 基因；
  3. 集合 C——A ∩ B 导入 STRING / Cytoscape（置信度 > 0.7），取 Degree、MCC 排名前 15–25 的枢纽基因。

三重交集保证候选在「差异表达、通路驱动、互作核心」三个维度同时突出，通常收敛到 10–30 个。肺癌数据模拟案例：

实验验证路径

  • 初级验证——qRT-PCR（独立样本）验证表达趋势、Western blot 检测蛋白水平、组织表达谱定位；
  • 机制深入——过表达/敲低（CRISPRi、siRNA）观察功能表型，下游靶标做 ChIP / 双荧光素酶，动物或类器官模型验证。
