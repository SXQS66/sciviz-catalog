🧬 Count · 原始计数
featureCounts / HTSeq
→ 比对到基因的 reads 数

🎯 核心

  • 非负整数，无标准化
  • 保留原始统计分布
  • DESeq2/edgeR 专用输入

⚠️ 局限

  • 不可跨样本/基因直接比较
  • 受文库大小 & 基因长度影响
💡 差异表达分析的「原始底片」
📏 RPKM · 单端长度校正
RPKM = (10⁹ × C) / (N × L)
C = 基因reads数
N = 总reads(百万)
L = 基因长度(kb)
🔄 顺序: 先文库 → 后长度
📅 2008年提出，单端测序
  • ✅ 同一样本内可比较不同基因
  • ❌ 不同样本总RPKM不一致 → 跨样本比较偏倚
  • 📉 逐渐被TPM替代
缺陷本质：标准化顺序导致总和不守恒
📐 FPKM · 双端片段校正
FPKM = (10⁹ × F) / (N × L)
F = 比对到基因的fragment数 (双端一对reads = 1 fragment)
N = 总fragment数(百万)  |  L = 基因长度(kb)

🔁 与RPKM

数学公式相同，reads → fragments。用于双端数据(Cufflinks/StringTie)。

🧩 相同缺陷

总FPKM样本间不守恒，跨样本比较受限。

⚡ 理解FPKM有助于解读早期文献，现代流程优先TPM
⚖️ TPM · 每百万转录本
先长度校正 → 后文库归一化
TPMᵢ = ( rᵢ / Lᵢ ) × ( 10⁶ / Σⱼ ( rⱼ / Lⱼ ) )
① rᵢ/Lᵢ 每千碱基reads (消除长度差异)
② 缩放至百万 总和 = 1,000,000
  • ✨ 跨样本直接可比：总和恒定，真实相对丰度
  • 📈 热图/PCA/聚类首选标准化方法
  • 🏆 Salmon/RSEM 等定量工具默认输出
🎯 因为总和固定，TPM让跨样本比较完全可信
