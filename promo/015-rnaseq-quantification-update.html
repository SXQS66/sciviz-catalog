RNA-seq定量更新

从原始 reads 到可比的丰度

本文是 No.008 的更新版，把 RNA-seq 定量的四种核心单位放进同一条流水线：Count 是 featureCounts / HTSeq 统计出的原始计数，一切的起点；RPKM / FPKM 先校文库再校长度，是历史经典的计量方式1；TPM 先校长度再缩放到每样本总和一百万，是跨样本比较的首选2。一句话记住分工：差异分析用 Count，跨样本可视化用 TPM。

Count：原始计数，差异分析的底片

Count 是比对后由 featureCounts / HTSeq 统计到的每个基因的 reads 数。它保留原始统计分布，是 DESeq23 / edgeR 等差异分析工具的专用输入——这些模型基于负二项分布直接对计数建模，不需要先做长度校正。

局限：Count 同时受文库大小和基因长度影响，不同样本之间、不同基因之间都不能直接比较数值大小，必须交给统计模型处理。

RPKM / FPKM：历史上的长度校正

RPKM（单端）在 2008 年由 Mortazavi 等人提出1，对 reads 数同时做文库大小与基因长度校正：

RPKM = (10⁹ × C) / (N × L)
C = 比对到基因的 reads 数
N = 样本总 reads 数（百万）
L = 基因长度（kb）

FPKM（双端）公式相同，只是把 reads 换成 fragment——双端数据中一对 reads 记为 1 个 fragment，是 Cufflinks / StringTie 一系工具的输出单位。二者只差输入类型，标准化顺序完全一致：先文库 → 后长度。

共同缺陷：标准化顺序导致各样本的 RPKM/FPKM 总和不守恒。某个高表达基因升高，会压低其他所有基因的数值，因此跨样本比较存在系统性偏倚——这也是 TPM 出现的直接原因。

TPM：交换顺序，总和恒定

TPM 先对每个基因做长度校正，再缩放到每样本总和为一百万：

TPMᵢ = ( rᵢ / Lᵢ ) × ( 10⁶ / Σⱼ ( rⱼ / Lⱼ ) )
① rᵢ/Lᵢ  每千碱基 reads 数（消除长度差异）
② 缩放至每样本总和 = 1,000,000（消除文库差异）

顺序交换后，每个样本的 TPM 总和恒定为 10⁶，因此 TPM 反映的是基因在转录组中的真实相对丰度，热图、PCA、聚类、多组学整合等跨样本分析都应优先使用 TPM2。Salmon、RSEM 等现代定量工具默认输出 TPM。

理性看待：总和恒定使 TPM 在相对丰度层面比 RPKM/FPKM 更稳健，但它仍受注释版本、基因长度估计方式和长度校正假设的影响——TPM 改善了跨样本可比性，并非「完全可信」的绝对定量。

四种单位一览：怎么选

单位文库校正长度校正样本间总和跨样本可比主要场景
Count❌❌不守恒❌差异分析（DESeq2 / edgeR）
RPKM / FPKM✅（先）✅（后）不守恒有偏历史文献解读
TPM✅（总和归一）✅（先）恒定 = 10⁶✅（首选）热图 / 聚类 / 多组学

标准流程可以概括为一条链：Count → DESeq2 做差异分析；TPM → 做可视化比较。从 Count 到 RPKM/FPKM 再到 TPM，计量方式的演进方向始终是让数据回归可解释的相对丰度，而不是追求单一「完美」单位。
