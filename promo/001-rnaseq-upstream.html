RNA-seq 上游分析：从 NCBI 到 Count 矩阵

从 SRA 下载数据到基因 Count 矩阵的完整上游流程：文件格式速查、质控、STAR 比对与 featureCounts 定量，附全套可运行命令。

RNA-seqSRA质控STAR上游分析

全流程一览

上游分析要回答一个问题：测序仪吐出的几十 G reads，如何变成一张「基因 × 样本」的 Count 矩阵？整条链路是固定五步，每一步的输入输出都不变：

步骤输入常用工具输出
① 获取数据SRA 登录号sra-tools（prefetch + fasterq-dump）FASTQ
② 质控FASTQFastQC · fastp4 · MultiQC5质控报告 + 清洗后 FASTQ
③ 比对FASTQ + 参考基因组STAR2（或 HISAT2）BAM
④ 定量BAM + GTF 注释featureCounts3基因 Count 矩阵
⑤ 交付下游Count 矩阵 + 样本信息表DESeq2 / edgeR（见 No.003）差异分析结果

环境准备（推荐 conda 一次装齐，并记录版本号）：

# 一次创建上游分析环境（bioconda 源）
conda create -n rnaseq -c bioconda -c conda-forge \
  sra-tools fastqc fastp star subread samtools multiqc
conda activate rnaseq

先认识文件：五分钟格式速查

格式内容典型文件
FASTA序列本身：一行以 > 开头的描述行 + 若干行序列字母参考基因组 Genome.fa、转录本 cDNA.fa
FASTQ序列 + 质量：每 4 行一条 read测序数据 SRR…_1.fastq.gz
SAM / BAM每条 read 比对到基因组的记录（位置、错配、比对质量）；BAM 是其压缩二进制版Aligned.sortedByCoord.out.bam
GTF/GFF基因结构注释：基因、转录本、外显子的坐标与属性genes.gtf（与基因组必须同版本）

FASTQ 的四行结构（质量行与序列行逐字符对应，等长）：

@SRR28453127.1 1 length=101
GATCGGAAGAGCACACGTCTGAACTCCAGTCACATCACGATCTCGTATGCCGTCTTCTGCTTGCGTACGATCGTTAGCCAGTACGTAGCTAGCATCGTACG
+
FFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFF:FF,FFF,FFF,F,FF,F,F,,F,F,

第 4 行质量字符用 Phred+33 编码：字符的 ASCII 值减 33 即质量值 Q，Q = −10·log₁₀(P)，P 为该碱基测错的概率。常见对照：

字符质量值含义
!Q0完全不可信（通常对应 N）
5Q20错误率 1%，勉强可用
FQ37错误率约 0.02%，良好
IQ40错误率 0.01%，优秀

两个易错点：① FASTQ 中 _1 / _2（或 R1/R2）是一对 read 的两端，顺序必须一一对应；② BAM 不能直接用 cat/head 查看，需 samtools view6 file.bam | head，或对排序后的 BAM 建 .bai 索引供 IGV 查看。

第一步：从 NCBI SRA 拿到 FASTQ

公共测序数据存于 SRA（Sequence Read Archive）1。检索入口：SRA 数据库——用疾病名/基因名检索，或从文献 Data availability 段落直接复制登录号。SRA 的编号是分层金字塔：

层级前缀示例含义
BioProjectPRJNA123456整个研究项目（最顶层）
StudySRP123456一次测序研究
SampleSRS1234567一个样本（对应一组分组信息）
ExperimentSRX1234567一个上机实验（文库 + 上机方案）
RunSRR1234567一次实际下机的数据，下载的基本单位

在 Run Selector（页面顶部 Send to → Run Selector）里可以按 SRS 逐行勾选，勾选后导出 SRR_Acc_List.txt（每行一个 SRR 号）。下载用 sra-tools 的两段式：先 prefetch 拉 SRA 原始文件，再 fasterq-dump 拆成 FASTQ：

# 单个 Run 下载并拆分
mkdir -p sra fastq
prefetch SRR28453127 -O sra/
fasterq-dump SRR28453127 -e 6 -O fastq/
gzip fastq/SRR28453127_1.fastq fastq/SRR28453127_2.fastq

# 批量下载：用 Run Selector 导出的 SRR 列表
cat SRR_Acc_List.txt | while read srr; do
  prefetch "$srr" -O sra/
  fasterq-dump "$srr" -e 6 -O fastq/
  gzip fastq/${srr}_1.fastq fastq/${srr}_2.fastq
done

命名即记录：双端数据拆出 _1/_2 两个文件（R1/R2）。把样本名与 SRR 号的对应关系存成一张 samplesheet 表（样本名、SRR、分组、批次），下游差异分析还要用。

第二步：质控——先看清数据再动手

质控分「看」与「洗」两步：FastQC 逐文件诊断，fastp 清洗并出报告，MultiQC 汇总所有样本。

# FastQC：对原始 FASTQ 逐文件出报告
mkdir -p qc/raw
fastqc -t 8 -o qc/raw fastq/*.fastq.gz

# fastp：去接头 + 掐低质量尾部 + 丢弃过短 reads
mkdir -p clean
fastp \
  -i fastq/SRR28453127_1.fastq.gz -I fastq/SRR28453127_2.fastq.gz \
  -o clean/SRR28453127_1.fq.gz  -O clean/SRR28453127_2.fq.gz \
  --detect_adapter_for_pe --qualified_quality_phred 20 \
  --length_required 36 --thread 8 \
  --json qc/SRR28453127.fastp.json --html qc/SRR28453127.fastp.html

FastQC 报告重点看四项：

指标健康标准异常时的处理
Per base sequence quality尾部中位 Q ≥ 30靠 fastp 的质量修剪补救
Adapter Content< 5%fastp 自动去接头
Duplication Levels适度即可（RNA-seq 天然偏高）显著偏高提示 PCR 过度扩增或起始量过低
Overrepresented sequences少量大批量单一序列提示污染（rRNA 等）
 
# MultiQC：把 FastQC、fastp、STAR、featureCounts 的报告汇成一份总表
multiqc qc/ clean/ star/ counts/ -o qc/multiqc

清洗要克制：现代数据的接头和低质量尾部通常很少，激进修剪反而丢数据。STAR 会软切比对不上的部分，所以质控的主要目标是去接头，而非把数据洗得越短越好。清洗后重跑 FastQC 确认改善。

第三步：比对——STAR 建索引与比对

参考基因组与注释建议从 GENCODE 或 Ensembl 下载，FASTA 与 GTF 必须取自同一注释版本（版本不一致是比对率偏低与注释错位的常见原因）。STAR2建一次索引，之后所有样本共用；人类/小鼠基因组建索引约需 30 GB 内存：

# 建索引：sjdbOverhang = read 长度 − 1（101bp 读长取 100）
STAR --runMode genomeGenerate --runThreadN 12 \
  --genomeDir star_index \
  --genomeFastaFiles Genome.fa \
  --sjdbGTFfile gencode.vM36.annotation.gtf \
  --sjdbOverhang 100

# 逐样本比对：输出按坐标排序的 BAM，并同时按基因计数
mkdir -p star
STAR --runThreadN 12 --genomeDir star_index \
  --readFilesIn clean/SRR28453127_1.fq.gz clean/SRR28453127_2.fq.gz \
  --readFilesCommand zcat \
  --outSAMtype BAM SortedByCoordinate \
  --quantMode GeneCounts \
  --outFileNamePrefix star/SRR28453127.

# 给 BAM 建索引（供 IGV 查看与下游工具使用）
samtools index star/SRR28453127.Aligned.sortedByCoord.out.bam

比对完成后先看 star/SRR28453127.Log.final.out，三个数字决定这批数据能不能往下走：

指标健康参考值偏低时先排查
Uniquely mapped reads %≥ 70%（细胞系/组织通常 75–90%）参考基因组物种/版本是否用错
% of reads mapped to multiple loci个位数rRNA 污染或注释版本过旧
Average mapped length接近原始读长插入片段过短或数据被过度修剪

同一项目内参数必须统一：所有样本用同一版本的工具、同一索引、同一参数跑完。混用比对结果会给下游引入批次假象。

关键一步：链特异性别搞错

建库试剂盒决定 reads 与基因方向的关系（链特异性），定量参数若与之不符，会静默丢掉约一半 reads。先确定链型，再全局统一：

文库类型常见试剂盒featureCounts -sSTAR ReadsPerGene 列
非链特异性普通 poly-A 建库0第 2 列
正向（forward）部分 ligation 法1第 3 列
反向（reverse）dUTP / TruSeq Stranded（最常见）2第 4 列

拿不准怎么办：打开 star/SRR28453127.ReadsPerGene.out.tab——第 2 列是非链特异性计数，第 3/4 列是两种方向计数。谁的数值明显更大，就说明数据是哪种链型：第 4 列大 → 反向（-s 2）。也可以用 RSeQC 的 infer_experiment.py 自动判断。

第四步：featureCounts 定量

featureCounts3（subread 套件）把 BAM 里的 reads 分配到 GTF 注释的外显子上，按 gene_id 汇总；一次传入所有样本的 BAM，直接得到合并矩阵：

# -p 双端模式；--countReadPairs 按 read pair 计数（subread ≥ 2.0）
mkdir -p counts
featureCounts -T 8 -p --countReadPairs \
  -t exon -g gene_id \
  -a gencode.vM36.annotation.gtf \
  -s 2 \
  -o counts/featureCounts.txt \
  star/*.Aligned.sortedByCoord.out.bam

输出的 counts/featureCounts.txt 前几行是注释信息，Geneid 列之后每列一个样本——这就是交给差异分析（DESeq2 / edgeR）的原始 Count 矩阵。三个硬性要求：

  • 差异分析必须用原始整数 Count，不要喂 TPM/FPKM（参见 No.015）；
  • 列的顺序与样本对应关系要记录在样本信息表里；
  • 富集分析前记得把 ENSEMBL ID 转成 ENTREZID（参见 No.020 / 036）。

STAR 自带计数 vs featureCounts：加 --quantMode GeneCounts 后 STAR 会顺带输出 ReadsPerGene.out.tab，可以直接用；但 featureCounts 支持多外显子 read 的精细分配规则与并行多样本合并，是论文方法学里更常见的写法。两者二选一即可，不要混用。

交付下游：一张清单

  • Count 矩阵：counts/featureCounts.txt（基因 × 样本，整数）；
  • 样本信息表：样本名、SRR 号、分组、批次——差异分析 design 公式的依据；
  • QC 存档：qc/multiqc_report.html + 各样本 Log.final.out 的比对率表；
  • 版本记录：sra-tools / STAR / subread 版本号，基因组与注释版本（如 Gencode vM36）——方法学部分直接照抄；
  • 下一步：ID 统一（No.020）→ 差异分析（DESeq2）→ 可视化与富集（No.034 / 036）。

可复现性提醒：「能跑出矩阵」只是底线。把每一步的版本号、参数和样本表存进分析目录，下一次换电脑或换人重跑时得到同样的结果，才算合格的上游分析。
